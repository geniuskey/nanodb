# NANoDB 홈 탭 요구사항 분석

## 1. 의도 분석

- **사용자 요청**: `references/NanoDB_홈탭_구성.pdf`를 참고해 기존 requirements를 필요한 만큼 업데이트한다.
- **요청 유형**: 기존 요구사항 보강
- **범위 추정**: 홈 탭, MVP 공통 요구사항, 구현 제외사항에 걸친 문서 변경
- **복잡도**: 단순
- **분석 깊이**: 최소
- **핵심 제약**: 1명이 8시간 안에 구현 가능한 해커톤 MVP 범위를 유지한다.

## 2. 기준 문서

- `references/NanoDB_홈탭_구성.pdf`: 심사용 홈 탭의 메시지와 발표 순서
- `requirements/nanodb-mvp-requirements.md`: MVP 기능·데이터·화면·API·완료 기준
- `requirements/home-tab-requirements.md`: 홈 탭 세부 기능과 수용 기준
- `requirements/constraints.md`: 의도적으로 구현하지 않는 범위

충돌 시 MVP 범위 문서와 제외사항을 우선하며, PDF의 전체 제품 구상은 로드맵으로 보존한다.

## 3. 핵심 결정

1. 홈은 첫 화면이자 발표 화면이며 `대의 → 근거 → 현재 기능 → 실제 KPI → 사용 흐름` 순서로 구성한다.
2. 실제 구현은 `Image → Measurement` 흐름에 집중한다.
3. PDF의 `Image → Label → Feature → Tool → Owner` 온톨로지는 제품 방향으로만 설명한다.
4. 윤곽 라벨링, 6종 피처 자동 계산, Tool 등록, Lineage, Report, 외부 API/Skill은 P2로 둔다.
5. PDF의 예시 KPI는 실제값으로 사용하지 않고 SQLite 집계값만 표시한다.
6. 공개 통계와 내부 KPI를 분리하며 공개 통계에는 기관과 발표 연도를 함께 표시한다.
7. 로그인과 역할별 권한은 MVP에서 제외한다.

## 4. 기능 요구사항 요약

### 4.1 홈과 내비게이션

- `/`에서 홈을 제공한다.
- NANoDB 로고, 확장명 `Nano Assets, Never orphaned Database`, 한국어 의미 `나노 자산은 고아가 되지 않는다`, 부제 `데이터는 쌓이고, 툴은 이어진다.`, 실제 이미지·측정 수와 기준 시각을 표시한다.
- 홈, 이미지 목록, 이미지 등록을 실제 동작 메뉴로 제공한다.
- 미구현 제품 메뉴를 노출하면 `준비 중` 또는 `P2`로 표시하고 클릭을 제공하지 않는다.

### 4.2 홈 본문과 CTA

- 제목, 세 가지 가치, MVP 범위, CTA, 공개 통계, 실제 KPI, 사용 흐름, 정책 순서를 유지한다.
- CTA는 이미지 둘러보기, 이미지 등록, 대상 이미지 선택 후 측정만 제공한다.
- 라벨링 시작, Tool 등록, API/Skill 호출은 활성 CTA로 제공하지 않는다.

### 4.3 실제 KPI

- 전체 이미지 수와 전체 측정 수를 SQLite 데이터에서 계산한다.
- 항목별 측정 평균에는 단위 `nm`와 표본 수 `n`을 표시한다.
- 집계 기준 시각을 표시한다.
- 빈 데이터에서는 0 또는 측정 없음을 표시한다.
- PDF 예시값, 라벨 완료율, Tool 생존율은 실제 KPI로 표시하지 않는다.

### 4.4 핵심 데모 기능

- PNG/JPEG SEM/TEM 이미지와 Product, Lot, Wafer, `nm/pixel`을 등록한다.
- 목록과 단일 검색어로 이미지를 찾는다.
- 원본 이미지 기준 두 점 좌표로 CD, Depth, Thickness를 측정한다.
- 계산된 측정값과 좌표를 저장·복원·선택·삭제한다.
- 원본 파일은 수정하지 않고 측정을 별도 파생 데이터로 저장한다.

## 5. 비기능 요구사항 요약

- 최신 Chrome 또는 Edge, 1280px 이상 데스크톱 시연을 우선한다.
- SQLite와 로컬 파일 저장소만 사용하며 외부 유료 서비스 없이 실행한다.
- 이미지 크기는 최대 20MB, 데모 데이터는 100건 이하를 전제로 한다.
- 목록과 상세 화면은 데모 환경에서 2초 이내 표시를 목표로 한다.
- 입력 오류와 빈 상태를 텍스트로 설명하며 색상만으로 상태를 구분하지 않는다.
- README에 1~2개 명령으로 실행하는 방법과 데모 순서를 기록한다.

## 6. 제외 범위

- 인증, 권한, SSO와 운영 보안
- 이미지 메타데이터 자동 추출과 대량 업로드
- 윤곽 라벨링, 검수, 버전, 자동 영상처리
- 6종 Hole 피처와 고급 계측 자동 계산
- Tool 계약·실행 이력·생존율
- 전체 온톨로지와 계보 그래프
- 고급 분석, 월간 리포트, 사용자용 OpenAPI와 에이전트 스킬
- 고가용성, 재해 복구, 클라우드 배포와 운영 관측성

## 7. 수용 기준

- 홈의 활성 CTA는 모두 구현된 화면으로 이동한다.
- 미구현 기능은 실행 가능한 UI로 오인되지 않는다.
- 이미지 또는 측정 추가 후 홈 KPI와 기준 시각이 갱신된다.
- 공개 통계에 기관과 연도가 표시되고 내부 KPI와 구분된다.
- 이미지 등록부터 두 점 측정, 저장, 새로고침 후 복원까지 동작한다.
- 잘못된 파일, 누락 값, 0 이하 보정값을 저장하지 않고 오류를 표시한다.
- 요구사항 식별자는 중복되지 않고 Markdown 문서가 정상적으로 렌더링된다.

## 8. 확장 설정

| 확장 | 선택 | 근거 |
| --- | --- | --- |
| Resiliency Baseline | 비활성화(B) | 8시간 PoC이며 고가용성·재해 복구가 제외 범위임 |
| Security Baseline | 비활성화(B) | 인증과 운영 보안을 제외한 로컬 데모임 |

## 9. 결과 요약

홈 탭 시안의 발표 구조와 제품 메시지는 유지하되, 데모가 실제 제공하는 이미지 등록·검색·수동 계측 흐름만 활성 기능으로 명시했다. 제품의 장기 온톨로지는 로드맵으로 분리하고, 예시 수치가 실제 데이터로 오인되는 위험을 제거했다.
