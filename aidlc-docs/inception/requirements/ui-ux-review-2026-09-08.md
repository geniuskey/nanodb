## 3. A그룹 — 구현됐지만 요구사항에 없는 기능 (문서 부채)

요구사항 없이 구현된 기능은 심사 항목 `AI-DLC`(25%)와 `완성도`(15%)에서 그대로 감점 요인이다. 요구사항 → 구현 추적이 끊긴 기능이기 때문이다.

### A-1. 도형 라벨링 (화살표·원 + 도형별 제품/Step/측정 항목 명)

- **구현 근거**: `alembic/versions/20260908_0003_create_annotations_table.py`, `src/backend/nanodb/services/annotation_service.py`, `src/backend/nanodb/api/routes.py:170-224` (POST/GET/PATCH), `src/frontend/src/measurement/AnnotationLayer.tsx`, `src/frontend/src/pages/MeasurementPage.tsx:258-283`
- **문서 상태**: 요구사항 ID 없음. 오히려 정반대의 서술이 세 곳에 있다.
  - `aidlc-docs/inception/requirements/requirements.md` 6절 제외 범위: "윤곽 라벨링, 관심 영역 관리, 검수, 버전과 자동 영상처리"
  - `requirements/constraints.md:95`: "Hole 윤곽 라벨링, 라벨 버전과 라벨 검수 상태"
  - `home-tab-requirements.md` HOM-011: "윤곽 라벨링 ... 을 현재 기능으로 서술하지 않는다"
- **구현상 결함 2건**
  1. **도형을 삭제할 수 없다.** `routes.py`에 annotation DELETE 엔드포인트가 없고 UI에도 삭제 버튼이 없다. 잘못 그린 도형은 이미지를 삭제하지 않는 한 영구히 남는다.
  2. **도형은 Context ZIP에 포함되지 않는다.** `export_builder.py`/`context_export_service.py`에 annotation 참조가 없다. 제품 명제(측정 근거를 AI 개발 컨텍스트로 재사용)에서 라벨링 데이터만 고아로 남는 구조다.
- **제안 방향**: 신규 요구사항군 `ANN-001~008`을 MVP 문서 3.7절로 신설하고, 제외 범위의 "윤곽 라벨링"을 "**자유 윤곽(폴리곤) 라벨링과 라벨 검수·버전**"으로 좁혀 구현된 2종 도형(arrow/circle)과 구분한다. HOM-011도 같은 표현으로 정정한다. DELETE 엔드포인트와 ZIP 포함 여부는 결정 필요(질문 1·2).

### A-2. TIFF 업로드와 브라우저 표시용 PNG 파생본

- **구현 근거**: `src/backend/nanodb/adapters/image_decoder.py:11-60` (`supported_formats = {PNG, JPEG, TIFF}`, `render_web_preview`), `alembic/.../20260908_0002_add_image_display_filename.py`, `ImageRegisterPage.tsx:56` (`accept=image/png,image/jpeg,image/tiff,.tif,.tiff`)
- **문서 상태 충돌**
  - IMG-001: "PNG 또는 JPEG 이미지 한 장" / IMG-005: "실제로 디코딩 가능한 PNG/JPEG인지 확인"
  - `README.md:164`: "현재 MVP의 브라우저 직접 등록 형식은 PNG/JPEG이며, TIFF 직접 업로드나 웹 표시 변환은 후속 범위입니다"
  - `requirements.md` 4.5·4.4절: TIFF는 데모 전에 수동 PNG 파생본을 준비하는 것으로 규정
- **제안 방향**: IMG-001/IMG-005를 PNG/JPEG/TIFF로 갱신하고, 신규 `IMG-007`(원본 보존 + 원본 픽셀 크기 유지 PNG 파생본 생성 + 파생본 서빙)과 `IMG-008`(파생본은 좌표를 1:1로 유지하며 리샘플링하지 않는다)을 추가한다. DAT-005의 수동 파생본 준비 절차는 앱 내 자동 파생과 구분해 남긴다. README 164행도 함께 정정한다.

### A-3. 이미지 삭제 (측정·도형·파일 cascade)

- **구현 근거**: `image_service.py:138-158`, `routes.py:118` (DELETE /api/images/{id}), `ImageListPage.tsx:47-67`, `MeasurementPage.tsx:205-222`
- **문서 상태**: 요구사항 ID 없음. RES-005는 측정 삭제만 규정한다. "원본 데이터 보호"가 MVP 핵심 가치인데 원본을 지우는 기능이 무규정 상태다.
- **제안 방향**: 신규 `CAT-006`(목록·상세에서 이미지 삭제, 삭제될 측정·도형 건수를 사전 고지, 확인 절차 필수)과 `CAT-007`(삭제는 DB 행 커밋 후 파일 삭제 순서, 실패 시 고아 파일만 남기고 행-파일 불일치를 만들지 않는다)을 추가한다. 3.4절 제목을 "저장된 측정 결과 조회 및 삭제"에서 "저장 데이터 조회와 삭제"로 넓힌다.

## 4. B그룹 — 요구사항·설계 문서 간 충돌 및 미이관

### B-1. 홈 CTA: 상위 문서 2종과 HOM v2가 정반대

- **제안 방향**: 결정 필요(질문 4). 세 상위 문서 중 어느 쪽이 정본인지 확정하고 나머지를 그에 맞춘다. 어떤 선택이든 "정본은 `home-tab-requirements.md`, 상위 문서는 요약만 유지하고 세부는 참조" 형태로 충돌 재발을 막는 규칙을 5.2절에 추가한다.

- **제안 방향**: 요구사항 확정 후 두 산출물을 현재 구현 기준으로 갱신한다(Construction 단계 작업으로 분리).

### B-3. 측정 화면 요구사항 5.5절의 부분 미구현

5.5절은 "오른쪽: **이미지 메타데이터**, 측정 항목, 계산 중인 값, 메모, 저장/초기화 버튼"을 요구한다.

- 구현은 헤더에 `Product · Lot · Wafer`만 표시한다(`MeasurementPage.tsx:246`).
- **화면 어디에도 `nm/pixel` 보정값, 원본 픽셀 크기, 등록 시각이 없다.** 측정값의 신뢰 근거 중 가장 중요한 캘리브레이션 값이 측정 중에 확인되지 않는다. `checks.json`·`context.md`에는 들어가지만 화면에는 없다.
- 이는 요구사항 4.4절("각 측정값은 최소한 원본 이미지, 두 점 좌표, 파라미터 종류, 보정값, 단위와 생성 시각까지 역추적할 수 있어야 한다")의 화면 구현 누락이다.
- **제안 방향**: `MEA-012`(측정 화면에 보정값·원본 픽셀 크기·등록 시각을 상시 표시) 추가. 이견 없는 항목으로 판단해 기본 반영 대상에 포함한다.

### B-4. README와 구현 상태 불일치

## 5. C그룹 — UI/UX 미구현·품질 격차

우선순위는 이 프로젝트의 심사 배점(사용성 15%, 완성도 15%)과 데모 리스크 기준이다.

### C-1 (높음). 정밀 측정 수단 부재 — 줌·팬 없음

- `styles.css`의 `.image-stage > img { max-width: 100%; max-height: 72vh; }`로 이미지는 **축소만** 된다. 확대·이동 수단이 없다.
- 요구사항은 "새로고침 전후 저장 좌표는 각 끝점 1px 이내"라는 **복원 정확도**를 규정하지만, 사용자가 애초에 원본 1px을 지정할 **입력 정확도** 수단이 없다. 예: 원본 4096px 이미지가 1000px로 렌더되면 화면 1px = 원본 4px이라 물리적으로 1px 지정이 불가능하다.
- **제안**: `MEA-013`(측정 화면에 배율 확대·이동을 제공하고, 배율과 무관하게 좌표는 원본 기준으로 계산한다), `MEA-014`(현재 배율과 화면 1px에 대응하는 원본 픽셀 수를 표시해 지정 가능한 정확도를 사용자가 알 수 있게 한다). 구현 범위는 결정 필요(질문 5).

### C-2 (높음). 도형 삭제 불가 (A-1 재기재)

되돌릴 수 없는 쓰기 동작이다. 데모 중 오조작이 화면에 영구히 남는다.

### C-3 (높음). 저장 측정을 수정할 수 없다

- 저장 후 두 점 위치·항목·메모를 고칠 방법이 없다. 삭제 후 재측정만 가능하다.
- 요구사항 Part I 문제 정의에는 "측정값의 수정과 검토 이력"이 유실 항목으로 적혀 있으나, MVP는 수정을 다루지 않는다.
- **제안**: MVP 범위 유지 시 제외 범위에 "저장 측정의 좌표·항목 수정과 수정 이력"을 **명시**해 미구현임을 정직하게 선언한다(현재는 언급조차 없어 누락처럼 보인다). 또는 메모만 수정 가능하게 좁힌다(질문 6).

### C-4 (높음). 삭제 확인이 `window.confirm`

- `ImageListPage.tsx:56`, `MeasurementPage.tsx:192,212`.
- 스타일·문구 통제 불가, 포커스 관리·스크린리더 대응이 브라우저에 종속, e2e 테스트가 브라우저 대화상자 처리에 의존한다. 파괴적 동작 3곳 전부가 이 방식이다.
- **제안**: `UIX-001`(파괴적 동작의 확인은 앱 내 대화상자로 제공하고, 삭제될 파생 데이터 건수를 명시하며, 포커스를 대화상자로 이동시키고 Esc로 취소할 수 있어야 한다).

### C-5 (높음). 성공 피드백 없음

- 측정 저장·삭제·도형 저장·이미지 삭제 성공 시 텍스트 알림이 없다. 목록이 조용히 바뀔 뿐이다.
- 요구사항 5.1절은 "성공과 실패 결과를 텍스트로 표시해야 하며 색상만으로 구분하지 않는다"를 명시하는데, **성공 쪽이 구현되지 않았다.**
- **제안**: `UIX-002`(쓰기 동작의 성공을 `role="status"` 텍스트로 알리고, 실패는 `role="alert"`를 유지한다).

### C-6 (중간). 폼 인라인 오류·필수 표시 없음

- `ImageRegisterPage.tsx`는 6개 입력의 모든 오류를 폼 하단 단일 `role="alert"` 한 줄로 표시한다. 어떤 필드가 문제인지 알 수 없다.
- `aria-invalid`, `aria-describedby`, `required` 속성, 라벨의 필수 표기가 모두 없다.
- Functional Design은 "validation error는 가능한 경우 입력 가까이에 표시한다"를 이미 요구한다 → **설계 대비 미구현**.
- **제안**: `IMG-009`(필수 입력 표시), `IMG-010`(필드별 오류를 해당 입력 근처에 표시하고 `aria-invalid`/`aria-describedby`로 연결, 첫 오류 필드로 포커스 이동).

### C-7 (중간). 측정 상호작용의 키보드 접근 불가

- 측정은 `<img onClick>`(`MeasurementPage.tsx:251`)에만 의존한다. 이미지는 포커스를 받지 않아 **키보드만으로는 측정을 시작조차 할 수 없다.** 도형 그리기도 포인터 드래그 전용이다.
- HOM-038의 포커스 요구는 홈에만 적용된다.
- **제안**: 결정 필요(질문 7). 최소안은 `UIX-003`(측정 화면의 키보드 대안 — 좌표 수치 직접 입력 또는 방향키 커서 이동 중 하나를 제공)이고, 대안은 제외 범위에 "포인터 장치 없는 측정"을 명시하는 것이다. 무결정 상태를 남기지 않는 것이 목적이다.

### C-8 (중간). 페이지별 문서 타이틀·랜드마크 부족

- `src/frontend/index.html:6`의 `<title>NANoDB</title>` 고정. SPA 라우팅 시 타이틀이 바뀌지 않아 탭·히스토리·스크린리더에서 화면을 구분할 수 없다.
- 본문 건너뛰기(skip link)가 없고, `main` 앞에 헤더+탭바 15개 요소를 지나야 한다.
- **제안**: `UIX-004`(라우트별 문서 타이틀 갱신), `UIX-005`(본문 건너뛰기 링크).

### C-9 (중간). 에러 경계·미정의 라우트 미처리

- React 에러 경계가 없다. 렌더 예외 시 흰 화면이 된다.
- `App.tsx`에 `*` 라우트가 없다. `/foo`는 헤더·탭바만 있는 빈 화면이 된다.
- **제안**: `UIX-006`(예상하지 못한 렌더 오류와 미정의 경로를 각각 복구 동선이 있는 화면으로 처리하고, 내부 상세는 노출하지 않는다). 후자는 Functional Design의 "존재하지 않는 Image는 일반 빈 화면이 아니라 대상 없음 상태로 표시" 규칙과 같은 원칙이다.

### C-10 (중간). 실패 상태에 재시도 동선이 없다

- 홈 KPI·이미지 목록·측정 상세 실패는 모두 텍스트 한 줄로 끝난다. 새로고침 외의 회복 수단이 없다.
- **제안**: `UIX-007`(조회 실패에 다시 시도 동작을 제공한다).

### C-11 (중간). 검색 UX 미세 결함

- 검색어 입력마다 `state`가 `loading`으로 바뀌어 목록 전체가 사라진다(`ImageListPage.tsx:39`) → 타이핑 중 깜빡임.
- 결과 건수 표시가 없다. 검색어 지우기 버튼이 없다.
- **제안**: `CAT-008`(필터 재조회 중에는 이전 결과를 유지하고 갱신 중임을 알린다), `CAT-009`(현재 조건의 결과 건수를 표시한다).

### C-12 (중간). 빈 상태 문구의 언어 불일치

- `HomePage.tsx:370`은 영문 `No images yet.`, 목록·측정 화면은 한국어. 심사·발표 화면에서 눈에 띈다.
- **제안**: `UIX-008`(사용자 표시 문구는 한국어로 통일하고, 빈 상태에는 원인과 다음 행동을 함께 적는다).

### C-13 (낮음). 로딩 표현이 텍스트 한 줄

- 이미지 카드 그리드가 뒤늦게 채워져 레이아웃이 밀린다. `recent-card img`는 `aspect-ratio`가 지정돼 있어 홈은 양호하나, `.image-card img`는 고정 크기라 목록은 괜찮고 측정 뷰어가 가장 크게 밀린다.
- **제안**: 경미. `UIX-009`로 "로딩 중 자리 확보"만 규정하고 구현은 P2로 둔다.

### C-14 (낮음). 홈 KPI를 클라이언트에서 집계

- SEM/TEM 구성과 등록 추이를 `/api/images` 전체 목록을 받아 프런트에서 계산한다(`HomePage.tsx:150-175`). 데모 100건 전제에서는 문제없다.
- **제안**: 비기능 요구사항에 "홈 구성·추이 집계는 데모 규모(100건 이하) 전제의 클라이언트 집계이며, 규모 확대 시 서버 집계로 이전한다"를 부기해 부채를 명시한다.

### C-15 (낮음). 반응형·다크모드 범위 선언 부재

- `@media (max-width: 800px)` 한 개만 있다. 측정 화면의 도형 그리기는 포인터 드래그 전제라 터치 환경 동작이 미검증이다.
- 다크모드 대응이 없다(`prefers-color-scheme` 미사용).
- **제안**: 비기능 요구사항에 "1280px 이상 데스크톱 + 최신 Chrome/Edge 마우스 입력을 지원 범위로 하고, 태블릿·모바일 터치 측정과 다크모드는 제외 범위"를 **명시**한다. 미구현을 결함이 아니라 선언된 범위로 만든다.

### C-16 (낮음). 도형 선택이 표 포커스에만 연동

- `MeasurementPage.tsx:266` — 행의 `onFocus`/`onBlur`로만 `activeAnnotationId`가 바뀐다. 이미지 위 도형을 클릭해 선택할 수 없고, 표에서 마우스를 올려도 강조되지 않는다. 저장 측정 목록(RES-003)과 상호작용 규칙이 다르다.
- **제안**: `ANN-006`(도형과 표 행은 양방향으로 같은 강조 상태를 가진다) — RES-003과 동일한 규칙을 도형에도 적용.
