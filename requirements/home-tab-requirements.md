# NANoDB 홈 탭 요구사항 v2 (최종 구현 기준)

> 기준 자료: `references/NANoDB_홈탭_v2.pdf`
> 적용 원칙: v2 시안의 스크롤 순서와 메시지는 반영하되, 이 MVP가 실제로 제공하는 백엔드(이미지·측정 두 테이블, `/api/summary`, `/api/images`)만으로 채운다. 미구현 기능(승인 워크플로·분석 엔진·파라미터 마스터·인증)은 동작하는 것처럼 표시하지 않고, 정직한 빈 상태 또는 로드맵으로 처리한다. 예시 숫자·가짜 분포는 대입하지 않는다.

## 1. 목적과 범위

홈은 NANoDB의 첫 화면이자 발표의 스크롤 순서다. 사용자는 홈만 보고도 다음을 이해할 수 있어야 한다.

1. NANoDB가 왜 필요한가 (대의)
2. 지금 실제로 얼마나 쌓였는가 (실측 KPI)
3. 최근 어떤 이미지가 들어왔는가
4. 앞으로 어디까지 가는가 (Phase 1~4)
5. 어떻게 만들었는가 (AI-DLC)
6. 어디서부터 쓰면 되는가 (사용 흐름)

v2 시안의 전체 제품 온톨로지 `Image → Label → Feature → Tool → Owner`는 제품 방향으로 보존한다. 이 MVP의 실제 연결은 `Image → Measurement → Development Context`이며, Measurement는 원본 이미지에서 파생된 두 점 계측 결과다.

### 1.1 v2와 MVP 현실의 간극 (핵심)

v2 시안은 승인 상태 KPI, Lot별 분포 박스플롯, 파라미터 마스터, 로그인·역할, 썸네일 variant, 유사 이미지 추천 등 더 넓은 백엔드를 전제한다. 이 MVP 백엔드는 **이미지·측정 두 테이블**만 갖는다. 따라서:

- **실데이터로 채우는 것:** 이미지 수(SEM/TEM 구성 포함), 저장 측정 수, 파라미터별(CD/Depth/Thickness) 평균·표본 수, 측정 구성, 이미지 등록 추이, 최근 등록 이미지.
- **정직한 빈 상태/로드맵으로 처리하는 것:** 승인 상태 KPI, Lot 분포·spec 비교 차트, 계보 그래프, 유사 이미지 추천 — 데이터가 없으므로 표시하지 않고 Phase 2~4 로드맵으로 설명한다.
- **하지 않는 것:** 없는 백엔드(승인/분석/마스터/인증)를 새로 구현하지 않는다. 가짜 수치·박스플롯을 그리지 않는다.

## 2. 용어와 표시 원칙

- **실측 KPI**: 현재 PostgreSQL 데이터에서 서버가 집계한 이미지·측정 수치. 예시값을 대신 표시하지 않는다.
- **로드맵**: 향후 구현할 승인 워크플로·분석 차트·계보·API·추천 기능. Phase 배지로만 표시하고 클릭 동작을 주지 않는다.
- **원본 read-only**: 업로드된 원본은 UI에서 수정·덮어쓰지 않고, 측정은 별도 파생 데이터로 저장한다.

## 3. 기능 요구사항

### 3.1 헤더와 내비게이션

- **HOM-001:** NANoDB 로고를 선택하면 홈(`/`)으로 이동해야 한다.
- **HOM-002:** 브랜드 확장명 `Nano Assets, Never orphaned Database`, 부제 `데이터는 쌓이고, 툴은 이어진다`를 히어로(대의) 영역에 표시해야 한다.
- **HOM-003:** 헤더 상태 영역에는 실제 이미지 수, 실제 측정 수, 집계 기준 시각을 표시해야 한다. 데이터가 없으면 `이미지 0 · 측정 0`으로 표시한다.
- **HOM-004:** 주 내비게이션은 최소 `홈`, `이미지DB`, `이미지 등록`을 제공하고 현재 위치를 표시해야 한다. 어느 경로에서도 현재 위치로 표시되는 탭은 하나뿐이어야 한다. `이미지 등록`은 `이미지DB`의 하위 경로이지만 별도 탭이므로 둘이 동시에 활성으로 보이지 않아야 한다.
- **HOM-005 (v2, 2026-09-08 개정 2):** 홈 본문은 읽는 문서로 유지하며 화면 이동은 주 내비게이션이 담당한다. v1의 히어로 CTA는 제거한 상태를 유지한다. **예외는 두 곳이다.** (1) `이렇게 쓰세요` 사용 흐름 섹션 끝의 `이미지 등록`·`이미지 둘러보기` CTA 두 개. 사용 순서를 방금 읽은 사용자가 그 자리에서 시작할 수 있어야 하기 때문이다. (2) 최근 등록 이미지 카드. 카드는 자기 이미지의 측정 화면으로 이동한다(HOM-023). 히어로·KPI·Phase·AI-DLC 섹션에는 여전히 링크를 두지 않는다.
- **HOM-006 (2026-09-08 개정 2):** 미구현 기능을 가리키는 로드맵 탭(라벨DB·피처·툴·계보·리포트·API)은 내비게이션에 두지 않는다. 주 내비게이션에는 실제로 열리는 화면만 노출한다. 로드맵은 Phase 섹션이 설명하므로 회색 비링크 탭을 여섯 개 더 둘 이유가 없고, 누를 수 없는 탭이 내비게이션의 절반을 차지하면 실제 이동 경로가 묻힌다.
- **HOM-007:** 로그인, 역할 배지, 권한별 메뉴는 표시하지 않는다. 정적 발표용 역할 문구도 실제 로그인 상태로 오인되지 않게 한다.

### 3.2 본문 순서

- **HOM-008:** 본문은 다음 순서를 유지한다. 데이터가 없어 채울 수 없는 섹션은 정직한 빈 상태/로드맵으로 두되, 순서는 유지한다.
  1. 소개 영상 (HOM-040)
  2. 대의와 세 가치
  3. 실측 KPI (지금 쌓인 데이터) — 파라미터 평균 + 이미지/측정 구성 + 등록 추이
  4. 최근 등록된 이미지
  5. NANoDB가 가는 길 (Phase 1~4)
  6. 어떻게 만들었나 (AI-DLC)
  7. 이렇게 쓰세요 (사용 흐름)
  8. 데이터 정책 한 줄

### 3.3 대의와 세 가치

- **HOM-009:** 히어로에는 좌측 로고와 우측 브랜드 문구·대의 제목·설명 문단을 둔다. 히어로 로고는 PNG 자산(`assets/logo/nanodb_logo_horizontal.png`), 헤더 로고는 SVG 자산을 사용한다. 대의 제목은 데이터와 도구가 담당자 변경 후에도 남는다는 목적을 한 문장으로 표현한다(예: `만드는 사람은 바뀌어도, 데이터와 도구는 회사에 남게`).
- **HOM-010:** 세 가치 카드는 `누구나 만든다`, `누구나 꺼내 쓴다`, `떠나도 남는다`로 구성하고, 설명은 MVP 사실만 담는다. 앱 내 AI 코드 생성이나 담당자 관리가 구현되었다고 표현하지 않는다.
- **HOM-011 (2026-09-08 개정 2):** `SEM Hole 피처 6종 자동 계산`, 자유 윤곽(폴리곤) 라벨링과 라벨 검수·승인 워크플로를 현재 기능으로 서술하지 않는다. 로드맵 문구로만 사용한다. 단, 실제로 구현된 **측정 라벨링(ANN-001~005)**은 현재 기능이므로 로드맵으로 표시하지 않는다. 둘을 혼동해 표기하지 않는다.

### 3.4 실측 KPI (지금 쌓인 데이터)

- **HOM-012:** 데이터 소스는 `GET /api/summary`다. 응답은 `image_count`, `measurement_count`, `calculated_at`, `parameters[]`(각 `parameter_type`, `count`, `mean_nm`)를 포함한다.
- **HOM-013:** KPI 타일은 최소 `이미지 수`, `저장 측정 수`, 그리고 표본 수 상위 파라미터 평균 2종을 표시한다. 평균 타일에는 값·단위 `nm`·표본 수 `n`을 함께 표시한다.
- **HOM-014:** 이미지 타일 보조 문구의 `SEM N장 · TEM N장`은 `GET /api/images` 목록에서 집계한다.
- **HOM-015:** 파라미터 평균이 없는 자리(측정 없음)는 `—`와 `측정이 아직 없습니다 (n=0)`로 표시하고, 예시 평균(예: 38.2nm)을 대입하지 않는다.
- **HOM-016:** KPI 영역 제목 옆에 집계 기준 시각(`calculated_at`)을 표시한다.
- **HOM-017:** 승인 상태 KPI(승인/검토/초안 건수), 라벨 완료율, 툴 생존율은 이 MVP 데이터 모델에서 계산할 수 없으므로 KPI로 표시하지 않는다.
- **HOM-018 (구성/추이):** 실측 데이터로 다음 막대를 그린다. 데이터가 없으면 빈 상태 문구로 대체한다.
  - 이미지 구성: SEM/TEM 비율 (`/api/images` 집계)
  - 측정 구성: CD/Depth/Thickness 건수 비율 (`summary.parameters` 집계)
  - 이미지 등록 추이: 최근 등록일별 건수 막대 (최대 14일분, `/api/images`의 `created_at`)
- **HOM-019:** v2 시안의 Lot별 분포 박스플롯·spec 비교 차트는 분석 엔진과 Lot 그룹핑·spec이 없으므로 그리지 않는다. Phase 3 로드맵으로 설명한다(가짜 박스플롯 금지).

### 3.5 최근 등록된 이미지

- **HOM-020:** `GET /api/images` 최신순 상위 6건을 카드 그리드로 표시한다. 각 카드는 원본 파일명과 `이미지 종류 · Lot · Wafer`를 보여준다.
- **HOM-021:** 썸네일은 원본 이미지(`file_url`)를 `loading="lazy"`로 표시한다. v2의 `?variant=thumbnail` 파생본은 미구현이므로 원본을 축소해 사용한다.
- **HOM-022:** 이미지가 없으면 `No images yet.` 빈 상태를 표시한다. 목록을 불러오지 못하면 `role="alert"` 텍스트로 알린다.
- **HOM-023 (2026-09-08 개정 2, HOM-005 예외):** 최근 이미지 카드는 자기 이미지의 측정 화면(`/images/{id}`)으로 이동하는 링크여야 한다. 카드 전체가 하나의 링크이며 접근 가능한 이름에 원본 파일명을 포함한다. 썸네일이 보이는데 눌러도 아무 일이 없는 상태는 이 섹션에서 가장 자주 막히는 지점이므로 허용하지 않는다.

### 3.6 왜 지금인가 (공개 통계) — 철회 (2026-09-08 개정 2)

`왜 지금인가` 섹션과 HOM-024~027은 철회한다. 이 섹션은 NANoDB 데이터가 아니라 외부 조사 수치를 옮겨 적은 것이어서, 홈이 실측만 보여준다는 원칙(HOM-015, HOM-017)과 나란히 두면 어떤 숫자가 이 저장소의 것인지 흐려진다. 필요성 설명은 대의 문구(HOM-009)가 이미 담당한다. HOM-024~027 번호는 다시 사용하지 않는다.

### 3.7 NANoDB가 가는 길 (Phase 1~4)

- **HOM-028:** Phase 카드는 4개(모은다·표준화한다·이어준다·제안한다)로 구성하고, 각 카드에 상태 배지·설명·근거 기능을 표시한다.
- **HOM-029 (2026-09-08 개정 2):** Phase 1은 `● 지금 동작`으로 표시하고, 이 MVP가 실제로 제공하는 기능(이미지 등록, nm/pixel 캘리브레이션, 두 점 측정 CD/Depth/Thickness, 측정 라벨링, 항목별 평균, 단일 검색, 측정·이미지 삭제, 저장·재확인, 개발 컨텍스트 내보내기)만 나열한다.
- **HOM-030 (2026-09-08 개정 2):** Phase 2는 `○ 다음`, Phase 3~4는 `○ 로드맵`(승인 워크플로·분석 차트·계보·API·추천)으로 표시한다. 단일 검색(CAT-003), 측정 삭제(RES-005), 항목별 평균(SUM-002)은 이미 구현됐으므로 Phase 2의 예고 항목이 아니라 Phase 1의 근거 기능으로 적는다. 구현된 기능을 예고로 표시하면 실제 기능이 없는 것처럼 읽힌다. v2 시안이 Phase 1에 넣은 승인/분석/API는 이 저장소에서는 아직 미구현이므로 후속 Phase로 재배치한다.
- **HOM-031:** Phase 카드는 `<a>`/버튼이 아닌 비대화형 요소로 렌더링하고, 미구현 기능을 동작하는 것처럼 표시하지 않는다.

### 3.8 어떻게 만들었나 (AI-DLC)

- **HOM-032:** AI-DLC 영역은 3개 카드(산출물 구조·핵심 설계 결정·협업하며 배운 것)로 구성하고, 실제 `aidlc-docs` 산출물과 설계 결정에 근거한다.
- **HOM-033:** 준비 시간·수정 횟수·검증 결과는 실제 기록에만 근거하며, 토큰 절감이나 정확도 향상을 예시 KPI로 표시하지 않는다.

### 3.9 사용 흐름과 정책

- **HOM-034:** `이렇게 쓰세요`는 번호가 붙은 4개 카드로 `이미지 등록 → 캘리브레이션 → 두 점 측정 → 저장·개발 컨텍스트 내보내기` 순서를 표시한다. 외부 AI 도구의 코드 생성·검증은 앱 외부 작업으로 구분한다.
- **HOM-034a (2026-09-08 신규):** 4개 카드 아래에 `이미지 등록`과 `이미지 둘러보기` CTA 두 개를 둔다. 두 CTA는 구현된 화면(`/images/new`, `/images`)으로만 연결한다. 이 섹션 외의 홈 본문에는 CTA를 추가하지 않는다(HOM-005).
- **HOM-035:** 정책 줄에는 `원본 read-only · 측정은 파생 데이터 · 모든 수치에 n·기준 시각 · 데모 데이터는 synthetic 또는 사용 권한 확인 자료`를 한 줄로 표시한다.

### 3.9.1 홈 소개 영상

- **HOM-040 (2026-09-08 개정 2):** 홈 최상단의 소개 영상은 저장소에 포함된 로컬 영상 파일을 `<video>`로 재생한다. 외부 임베드와 서드파티 스크립트를 쓰지 않는다. 다음을 함께 만족해야 한다.
  - 재생 컨트롤을 제공하고, 영상 아래에 영상 없이도 홈 내용만으로 이해할 수 있다는 안내 문구를 둔다.
  - `prefers-reduced-motion`을 선택한 사용자에게는 자동 재생하지 않는다. 이때도 컨트롤은 그대로 제공해 직접 재생할 수 있어야 한다.
  - 영상은 보조 자료이며 앱 기능 근거로 사용하지 않는다. 영상이 재생되지 않아도 홈의 나머지 섹션은 그대로 읽을 수 있어야 한다.
  - 로컬 파일이므로 폐쇄망·오프라인 심사 환경에서도 외부 네트워크 없이 재생된다. 홈에는 런타임 외부 의존이 남아 있지 않다.

### 3.10 상태와 접근성

- **HOM-036:** KPI 로딩은 `role="status"`, 실패는 `role="alert"` 텍스트로 알리고, 실패 시 예시 숫자를 KPI로 대체하지 않는다.
- **HOM-037:** KPI/최근 이미지가 실패해도 정적 섹션(소개 영상·대의·Phase·AI-DLC·사용 흐름·정책)은 계속 렌더링한다(부분 실패에 강건).
- **HOM-038:** 모든 대화형 요소는 키보드 포커스가 보여야 하며 포커스 링에 `--accent`를 사용한다. 로드맵 요소는 탭 포커스를 받지 않는다.
- **HOM-039:** 1280px 데스크톱을 기준으로 하되 800px 이하에서는 카드 그리드를 1열(최근 이미지는 2열)로 접고 로고·실측 KPI 의미를 유지한다.

## 5. 수용 기준

- 홈은 소개 영상 → 대의·세 가치 → 실측 KPI → 최근 이미지 → Phase 1~4 → AI-DLC → 사용 흐름 → 정책 순서를 유지한다.
- 이미지 또는 측정을 추가한 뒤 홈을 다시 열면 실측 KPI·구성·추이·기준 시각이 갱신된다.
- 빈 데이터베이스에서도 예시 숫자가 KPI로 노출되지 않으며, 파라미터 평균 빈 자리는 `n=0`로 표시된다.
- 히어로 CTA는 제거되어 있고, 홈 본문의 이동 링크는 사용 흐름 섹션의 CTA 2개와 최근 이미지 카드뿐이다(HOM-005, HOM-023, HOM-034a). 모두 구현된 화면으로 이동한다.
- 최근 이미지 카드를 누르면 그 이미지의 측정 화면이 열린다(HOM-023).
- 내비게이션에는 누를 수 없는 로드맵 탭이 없다(HOM-006).
- 소개 영상은 외부 요청 없이 재생되며, 재생되지 않아도 홈의 나머지 섹션을 읽을 수 있다(HOM-040).
- 측정 라벨링은 구현된 기능으로 표기되고, 자유 윤곽 라벨링·검수는 로드맵으로 표기된다(HOM-011).
- Phase 2~4, 승인 KPI, Lot 분포 차트는 클릭 가능한 기능처럼 보이지 않고 로드맵/빈 상태로 표시된다.
- KPI나 최근 이미지 로딩이 실패해도 정적 섹션은 계속 보인다.
- 원본 read-only와 측정 파생 데이터의 구분이 정책 문구에 드러난다.

| v1 (`NanoDB_홈탭_구성.pdf`) | v2 (`NANoDB_홈탭_v2.pdf`, 현재 구현) |

## 7. 시각 디자인
