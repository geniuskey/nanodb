# NANoDB 홈 탭 요구사항

> 기준 자료: `references/NanoDB_홈탭_구성.pdf`  
> 적용 원칙: 심사용 메시지와 발표 흐름은 반영하되, 3일 MVP에서 구현하지 않는 기능을 동작하는 것처럼 표현하지 않는다.

## 1. 목적과 범위

홈은 NANoDB의 첫 화면이자 해커톤 발표의 스크롤 순서다. 사용자는 홈만 보고도 다음 내용을 이해할 수 있어야 한다.

1. 왜 NANoDB가 필요한가
2. 어떤 이미지와 데이터를 다루는가
3. 지금 시연할 수 있는 기능이 무엇인가
4. 실제로 얼마나 데이터가 쌓였는가
5. 어디서부터 사용하면 되는가

PDF가 제시한 전체 제품 온톨로지 `Image → Label → Feature → Tool → Owner`는 제품 방향으로 보존한다. MVP의 연결은 `Image → Measurement → Development Context`이며, Measurement는 원본 이미지에서 파생된 두 점 계측 결과다. 내보낸 컨텍스트를 기존 AI 개발 도구에서 사용해 분석 코드를 생성·검증하는 과정은 앱 외부의 데모로 구분한다.

## 2. 용어와 표시 원칙

- **공개 통계**: NANoDB 필요성을 설명하는 외부 조사 수치. 출처명과 발표 연도를 함께 표시한다.
- **실제 KPI**: 현재 PostgreSQL 데이터에서 계산한 이미지·측정 수치. 예시값을 대신 표시하지 않는다.
- **로드맵**: 향후 구현할 Label, Feature, Tool, Owner/Lineage, Report, API 기능. 비활성 상태 또는 `P2` 배지로 표시한다.
- **원본 read-only**: 업로드된 원본은 웹 UI에서 수정하거나 덮어쓰지 않고, 측정은 별도 파생 데이터로 저장한다는 뜻이다.
- 홈에서 `라벨`이라는 말은 윤곽 라벨 기능이 실제 구현되었을 때만 데이터 건수 의미로 사용한다. MVP에서는 `측정`으로 표기한다.

## 3. 기능 요구사항

### 3.1 헤더와 내비게이션

- **HOM-001:** NANoDB 로고를 선택하면 홈(`/`)으로 이동해야 한다.
- **HOM-002:** 브랜드 확장명 `Nano Assets, Never orphaned Database`, 부제 `데이터는 쌓이고, 툴은 이어진다.`를 데스크톱 헤더 또는 히어로 영역에 표시해야 한다.
- **HOM-003:** 헤더 상태 영역에는 실제 이미지 수, 실제 측정 수, 집계 기준 시각을 표시해야 한다.
- **HOM-004:** 주 내비게이션은 최소 `홈`, `이미지DB`, `이미지 등록`을 제공하고 현재 위치를 표시해야 한다.
- **HOM-005:** LabelDB, Feature, Tool, Owner/Lineage, Report, API를 전체 제품 방향으로 노출할 경우, 미구현 항목은 `준비 중` 또는 `P2`로 표시하고 클릭 동작을 제공하지 않아야 한다.
- **HOM-006:** 로그인, 역할 배지와 권한별 메뉴는 표시하지 않아야 한다. 정적인 발표용 역할 문구도 실제 로그인 상태로 오인되지 않게 해야 한다.

### 3.2 본문 순서와 메시지

- **HOM-007:** 본문은 다음 순서를 유지해야 한다. P1 공개 통계를 생략하면 다음 섹션이 그 자리를 당겨 이어진다.
  1. 대의와 제품 한 문장
  2. 세 가지 가치
  3. 처리 대상과 MVP 범위
  4. 핵심 CTA
  5. `왜 지금인가` 공개 통계
  6. 실제 데이터 KPI
  7. 사용 흐름
  8. 데이터 정책
- **HOM-008:** 대표 제목은 데이터와 도구가 담당자 변경 후에도 이어진다는 제품 목적을 설명해야 한다.
- **HOM-009:** 세 가지 가치는 `누구나 만든다`, `누구나 꺼내 쓴다`, `떠나도 남는다`로 구성해야 한다.
- **HOM-010:** 제품 한 문장은 `반도체 이미지와 측정 근거를 축적하고, AI 기반 분석 소프트웨어 개발에 필요한 컨텍스트와 검증 데이터로 재사용한다`로 설명한다. 현재 기능은 SEM/TEM 등록·조회, 두 점 계측·복원과 개발 컨텍스트 내보내기이며, 구현 전에는 예정 상태로 표시한다. 검색은 P1을 실제 구현한 경우에만 소개한다.
- **HOM-011:** PDF의 `SEM Hole 피처 6종 자동 계산`이나 윤곽 라벨링을 현재 기능이라고 서술하지 않아야 한다. 이는 로드맵 문구로만 사용할 수 있다.

### 3.3 CTA

- **HOM-012:** Primary CTA `이미지 둘러보기`는 이미지 목록으로 이동해야 한다.
- **HOM-013:** Secondary CTA `이미지 등록`은 등록 화면으로 이동해야 한다.
- **HOM-014:** 측정 CTA는 대상 이미지가 있어야 수행할 수 있음을 나타내며, 이미지 목록 또는 선택된 이미지의 측정 화면으로 이동해야 한다.
- **HOM-015:** 미구현 `라벨링 시작`, `내 툴 등록`, `API/스킬 호출`은 활성 CTA로 표시하지 않아야 한다.

### 3.4 공개 근거

- **HOM-016 (P1):** `왜 지금인가` 영역은 최대 네 개의 짧은 카드로 제한한다.
- **HOM-017 (P1):** 각 카드에는 수치, 수치가 뜻하는 바, 출처 기관, 발표 연도를 표시해야 한다.
- **HOM-018 (P1):** 외부 통계는 정적 콘텐츠로 제공하며 런타임 외부 API에 의존하지 않아야 한다.
- **HOM-019 (P1):** 오래된 조사 수치를 현재 실측값처럼 표현하지 않아야 하며, 조사 연도를 숨기지 않아야 한다.
- **HOM-020 (P1):** 통계 상세 URL은 새 탭 링크 또는 출처 표기로 제공할 수 있다. 공간이 부족하면 네 개 카드 중 일부를 제거할 수 있다.

### 3.5 실제 KPI

- **HOM-021:** 실제 KPI 영역은 최소 전체 이미지 수와 전체 측정 수를 서버 집계 결과로 표시해야 한다.
- **HOM-022 (P1):** 항목별 측정 카드에는 측정 종류, 평균값, 단위 `nm`, 표본 수 `n`을 표시해야 한다.
- **HOM-023:** KPI 영역 제목 옆에 집계 기준 시각을 표시해야 한다.
- **HOM-024:** 데이터가 없으면 `0`, `n=0` 또는 `측정 없음`을 표시하고 PDF 예시값(예: 1,240, 812, 38.2 nm)을 대입하지 않아야 한다.
- **HOM-025:** 도구 생존율, 라벨 완료율, 검수 건수는 MVP 데이터 모델에서 계산할 수 없으므로 KPI로 표시하지 않아야 한다.

### 3.6 사용 흐름과 정책

- **HOM-026:** 앱 흐름은 `이미지 등록 → 두 점 측정 → 저장·재확인 → 개발 컨텍스트 내보내기`로 표시한다. 이후 `기존 AI 도구에서 코드 생성 → 검토·실행·검증`은 앱 외부 작업으로 별도 설명한다.
- **HOM-027:** 정책 줄에는 `원본 read-only`, `측정은 파생 데이터`, `실제 수치에는 n·기준 시각`, `데모 이미지는 synthetic 또는 공개 사용 가능 자료`를 표시해야 한다.
- **HOM-028:** 모바일에서는 슬로건과 보조 설명을 숨길 수 있으나, 로고·주 CTA·실제 KPI의 의미는 유지해야 한다. 모바일 전용 최적화는 완료 기준이 아니다.

- **HOM-029:** 개발 컨텍스트 CTA는 이미지 선택 또는 선택된 이미지의 내보내기로 연결한다. 미구현이면 비활성 예정 표시를 하고, 측정이 없으면 저장 측정이 필요함을 안내한다.
- **HOM-030:** `누구나 만든다`는 데이터 계약과 개발 요청 템플릿 재사용, `누구나 꺼내 쓴다`는 저장 데이터와 측정 근거 조회, `떠나도 남는다`는 원본과 측정 근거의 보존으로 설명한다. 앱 내 AI 코드 생성이나 담당자 관리가 구현되었다고 표현하지 않는다.
- **HOM-031:** 앱 기능 완료, AI 개발 데모 실행, 후속 비전을 구분한다. 준비 시간·수정 횟수·검증 결과는 실제 평가 기록에만 근거하며 토큰 절감이나 정확도 향상을 예시 KPI로 표시하지 않는다.

## 4. 콘텐츠 우선순위

| 우선순위 | 반드시 포함 | 축소 가능 |
| --- | --- | --- |
| P0 | 제목, 세 가치, MVP 범위, 실제 동작 CTA, 이미지/측정 KPI, 4단계 사용 흐름, 짧은 정책 줄 | 아니요 |
| P1 | 공개 통계 카드와 출처, 항목별 평균, 정책 상세 설명 | 시간 부족 시 생략·표현 축소 |
| P2 | 전체 제품 탭, 온톨로지 설명, Tool 생존율, Lineage, Report, API/Skill 안내 | 비활성 로드맵 표기만 허용 |

## 5. 수용 기준

- 첫 진입 시 제목과 이미지 목록 CTA가 1280px 너비에서 스크롤 없이 보인다.
- 홈은 대의·세 가치 → MVP 범위·핵심 CTA → 공개 근거(P1) → 실제 KPI → 사용 흐름 → 짧은 데이터 정책 순서를 유지한다.
- 이미지 또는 측정을 추가한 뒤 홈을 다시 열면 실제 KPI와 기준 시각이 갱신된다.
- 빈 데이터베이스에서도 예시 숫자가 실제 KPI로 노출되지 않는다.
- P1 공개 통계를 표시한다면 출처 기관과 발표 연도가 보인다.
- 모든 활성 CTA가 구현된 경로로 이동한다.
- 미구현 기능은 클릭 가능한 탭이나 버튼처럼 보이지 않는다.
- 원본 이미지와 측정 파생 데이터의 구분이 홈의 정책 문구에 드러난다.
- 개발 컨텍스트의 목적과 진입 경로가 보이며, 외부 AI 도구의 코드 생성·검증을 앱 내 기능으로 오인하지 않는다.

## 6. PDF 시안과 MVP의 차이

| PDF 시안 | 3일 MVP 적용 |
| --- | --- |
| 이미지 수 · 라벨 수 · 갱신 시각 | 이미지 수 · 측정 수 · 집계 기준 시각 |
| 역할 배지 · 로그인 | 제외 |
| SEM Hole 윤곽 라벨링과 검수 | 제외, 두 점 수동 계측으로 대체 |
| CDx · CDy · 대각 CD · EPE · 곡률 · 링 두께 자동 산출 | 제외, CD/Depth/Thickness 수동 계측 유지 |
| 툴 등록 · 생존율 | P2 로드맵 |
| Image → Label → Feature → Tool → Owner 계보 | 제품 방향 설명만 유지, 구현은 Image → Measurement → Development Context |
| API · 에이전트 스킬 | P2 로드맵, 내부 MVP API만 사용 |
| 1,240 · 812 · 38.2 nm 등 | 예시값이므로 실제 KPI에 사용 금지 |

## 7. 시각 디자인 스펙 (PDF 시안 기반)

> 근거: `references/NanoDB_홈탭_구성.pdf` 1페이지 홈 시안.
> 원칙: **모양은 PDF, 내용은 MVP**. PDF의 비주얼 언어(팔레트·카드·탭바·섹션 리듬)는 충실히 재현하되, 로드맵 기능은 P2 비활성으로, 수치는 실제 집계값으로만 채운다. 이 절과 3장의 기능 요구사항(HOM-001~031)이 충돌하면 3장을 우선한다.

### 7.1 디자인 원칙

- **HOM-032:** 홈은 밝은 배경 위의 카드 기반 레이아웃이어야 한다. 색으로 채운 히어로 배너가 아니라, 큰 검정 제목 + 흰 카드 그리드로 구성한다(PDF 시안과 동일).
- **HOM-033:** 강조색은 인디고 계열 단색이며, 모든 화면(홈·목록·등록·측정)에서 동일한 토큰을 사용해 일관성을 유지한다.
- **HOM-034:** 상태·강조를 색상만으로 전달하지 않는다. 텍스트 라벨, 아이콘 또는 밑줄을 함께 사용한다(HOM-006, 5장 공통 원칙과 일치).

### 7.3 타이포그래피와 간격

- **HOM-035:** 서체는 Inter 계열 sans-serif. h1은 `clamp(2.2rem, 4.4vw, 3.6rem)`, `font-weight: 800`, `letter-spacing: -0.03em`로 크게 표시한다.
- **HOM-036:** 본문 최대 폭은 약 1180px 중앙 정렬. 섹션 간 세로 간격은 최소 56px, 카드 라운드는 16~18px, 카드 패딩은 20~24px, 카드 그리드 간격은 16~20px로 통일한다.

### 7.4 헤더와 탭바

- **HOM-037:** 전역 헤더는 좌측에 NANoDB 워드마크(로고 링크, HOM-001), 브랜드 확장명·부제(HOM-002), 우측에 실제 데이터 상태 pill을 배치한다. 상태 pill은 `이미지 N · 측정 N · 기준 시각`을 실제 집계값으로 표시한다(HOM-003). 데이터가 없으면 `이미지 0 · 측정 0`으로 표시한다.
- **HOM-038:** 헤더에는 역할 배지나 `로그인`을 표시하지 않는다. PDF의 `역할: 엔지니어 · 로그인`은 재현하지 않는다(HOM-006, MVP 인증 제외).
- **HOM-039:** 탭바는 PDF처럼 2줄 항목(메인 라벨 + 작은 힌트)으로 구성한다. 활성 탭은 인디고 밑줄과 진한 텍스트로 강조한다.
  - 실제 이동 탭(링크): `홈`(대의), `이미지DB`(찾기 → 이미지 목록), `이미지 등록`(작업 → 등록 화면).
  - 로드맵 탭(비링크, `--p2` 회색, `준비 중`/`P2` 힌트, 클릭·포커스 이동 없음): `라벨DB`, `피처`, `툴`, `계보`, `리포트`, `API`.
- **HOM-040:** 로드맵 탭은 `<a>`/버튼이 아닌 비대화형 요소로 렌더링하고 `aria-disabled`와 안내 title을 부여한다(HOM-005와 일치).

### 7.5 홈 본문 컴포넌트

- **HOM-041 (대의):** eyebrow에 확장명 `Nano Assets, Never orphaned Database`, h1은 데이터·도구가 담당자 변경 후에도 남는다는 대의를 한 문장으로 표현한다(예: `만드는 사람은 바뀌어도, 데이터와 도구는 회사에 남게`, HOM-008). 이어서 처리 대상·MVP 범위를 설명하는 히어로 문단을 둔다.
- **HOM-042 (세 가치 카드):** `누구나 만든다 · 누구나 꺼내 쓴다 · 떠나도 남는다` 3개를 흰 카드 그리드로 표시하고, 각 제목은 인디고, 설명은 MVP 사실만 담는다(HOM-009, HOM-030).
- **HOM-043 (CTA):** primary `이미지 둘러보기`(인디고 채움, → 목록), secondary `이미지 등록`(테두리, → 등록)을 나란히 둔다. 측정·컨텍스트 내보내기는 대상 이미지가 필요함을 보조 문구로 안내한다(HOM-012~014, HOM-029). `라벨링 시작`·`내 툴 등록`·`API/스킬 호출`은 활성 CTA로 표시하지 않는다(HOM-015).
- **HOM-044 (왜 지금인가, P1):** 공개 통계 카드는 큰 수치 + 진행바(`--accent`/`--accent-track`) + 의미 + 출처 기관 + 발표 연도로 구성한다(HOM-016~020). 실제 KPI와 시각적으로 구분되도록 별도 섹션·라벨을 둔다.
- **HOM-045 (실제 데이터 KPI):** PDF의 `이번 달 숫자` 카드 스타일을 재사용하되 값은 서버 집계값만 표시한다. 최소 `등록 이미지 수`·`저장 측정 수`와 `집계 기준 시각`을 카드로 보여주고 큰 숫자에 `--accent`를 쓴다. PDF의 예시값(1,240·812·65%·CDx 38.2nm·11/17)과 라벨 완료율·툴 생존율은 표시하지 않는다(HOM-024, HOM-025).
- **HOM-046 (사용 흐름):** `이렇게 쓰세요`는 번호가 붙은 4개 카드(`--accent-tint` 배경)로, `이미지 등록 → 두 점 측정 → 저장·재확인 → 개발 컨텍스트 내보내기` 순서를 표시한다. 이후 `기존 AI 도구에서 코드 생성 → 검토·실행·검증`은 앱 외부 작업으로 별도 표기한다(HOM-026).
- **HOM-047 (정책 줄):** `원본 read-only · 측정은 파생 데이터 · 실제 수치에는 n·기준 시각 · 데모 이미지는 synthetic 또는 공개 사용 가능 자료`를 한 줄 캡션으로 표시한다(HOM-027).

### 7.6 상태와 접근성

- **HOM-048:** 로딩은 `role="status"`, 실패는 `role="alert"` 텍스트로 알리고, 실패 시 예시 숫자를 KPI로 대체 표시하지 않는다(HOM-024와 일치).
- **HOM-049:** 모든 대화형 요소는 키보드 포커스가 보여야 하며 포커스 링에 `--accent`를 사용한다. 로드맵(P2) 요소는 탭 포커스를 받지 않는다.
- **HOM-050:** 1280px 데스크톱을 기준으로 하되 800px 이하에서는 카드 그리드를 1열로 접고 로고·주 CTA·실제 KPI 의미를 유지한다(HOM-028).
