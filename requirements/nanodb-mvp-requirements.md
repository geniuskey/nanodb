# NANoDB 8시간 해커톤 MVP 요구사항 정의서

> 문서 목적: 기존 NANoDB의 제품 의도를 유지하면서, 1명이 8시간 안에 구현하고 시연할 수 있는 범위를 정의한다.
> 범위 기준: 완성도 높은 하나의 핵심 흐름을 우선하며, 운영 환경 수준의 기능은 포함하지 않는다.

홈 탭의 메시지, 정보 구조, 실제값/예시값 구분은 [`home-tab-requirements.md`](./home-tab-requirements.md)를 함께 따른다. 두 문서가 충돌하면 이 문서의 8시간 MVP 범위와 [`constraints.md`](./constraints.md)의 제외사항을 우선한다.

## 1. 프로젝트 개요

### 1.1 서비스 한 줄 정의

NANoDB는 `Nano Assets, Never orphaned Database`의 약자다. `나노 자산은 고아가 되지 않는다`는 의미 아래 SEM/TEM 이미지를 제조 식별정보와 함께 등록하고, 이미지 위에서 두 점을 선택해 실제 길이를 측정·저장하는 경량 웹 애플리케이션이다. 부제는 `데이터는 쌓이고, 툴은 이어진다.`다.

### 1.2 해결하려는 문제

- SEM/TEM 이미지와 측정 결과가 파일 폴더와 스프레드시트에 나뉘어 보관된다.
- 측정값만 남고 어떤 이미지의 어느 위치를 측정했는지 알기 어렵다.
- Product, Lot, Wafer 정보와 이미지 및 측정값을 함께 검색하기 어렵다.

### 1.3 MVP 핵심 가치

- 이미지, 제조 식별정보, 측정 위치, 측정값을 하나의 흐름으로 연결한다.
- 별도 데스크톱 도구 없이 브라우저에서 기본 치수를 측정한다.
- 저장한 결과를 다시 열었을 때 측정 위치와 값을 재현한다.
- 홈 탭에서 `왜 필요한가 → 무엇을 하는가 → 실제 축적 수치 → 사용 흐름`을 한 번의 스크롤로 설명한다.

### 1.4 대표 데모 시나리오

1. 사용자가 PNG 또는 JPEG 형식의 SEM/TEM 이미지 한 장을 등록한다.
2. Product, Lot, Wafer와 이미지의 `nm/pixel` 보정값을 입력한다.
3. 등록된 이미지를 상세 화면에서 연다.
4. CD, Depth 또는 Thickness 중 측정 항목을 선택한다.
5. 이미지 위의 두 점을 차례로 클릭한다.
6. 시스템이 픽셀 거리와 보정값을 이용해 실제 길이를 계산한다.
7. 사용자가 측정 결과를 저장한다.
8. 이미지 상세 화면 또는 측정 목록에서 측정선, 값, 제조 식별정보를 다시 확인한다.

## 2. 사용자와 서비스 구성

### 2.1 사용자

- **분석자 1종**만 둔다.
- 로그인과 역할 구분 없이 모든 화면을 사용할 수 있다.
- 한 브라우저에서 로컬 또는 데모 서버에 접속하는 사용 환경을 전제로 한다.

### 2.2 주요 구성 요소

- **홈 화면**: 서비스 목적, 공개 근거, 실제 KPI, 핵심 사용 흐름과 진입 CTA
- **이미지 목록 화면**: 등록된 이미지 조회와 간단한 검색
- **이미지 등록 화면**: 이미지 파일, 제조 식별정보, 보정값 입력
- **측정 화면**: 이미지 표시, 두 점 측정, 결과 저장 및 조회
- **서버**: 이미지와 측정 데이터 저장 및 조회
- **저장소**: 로컬 파일 디렉터리와 SQLite 데이터베이스

## 3. 핵심 기능 요구사항

요구사항은 다음 두 등급으로 실행한다. 본 문서에 없는 기능은 해커톤 MVP 범위가 아니다.

- **P0 (Demo Gate)**: 하나라도 실패하면 핵심 데모가 완료되지 않은 것으로 본다.
- **P1 (Stretch)**: P0가 통합 검증된 뒤에만 구현한다. 미완료여도 핵심 데모 실패로 보지 않는다.

| 우선순위 | 요구사항 ID |
| --- | --- |
| P0 | IMG-001~006, CAT-001~002, CAT-004~005, MEA-001~011, RES-001~004, RES-006, SUM-001, SUM-003~005, DAT-001~007 |
| P1 | CAT-003, RES-005, SUM-002 |

### 3.1 이미지 등록

**목적**: 분석 대상 이미지와 최소 제조 식별정보를 함께 저장한다.

**기능 요구사항**:

- **IMG-001:** 사용자는 PNG 또는 JPEG 이미지 한 장을 선택해 등록할 수 있어야 한다.
- **IMG-002:** 등록 시 다음 정보를 입력할 수 있어야 한다.
  - 이미지 종류: SEM 또는 TEM
  - Product ID
  - Lot ID
  - Wafer ID
  - 보정값: 양수인 `nm/pixel`
- **IMG-003:** 원본 파일명과 등록 시각은 시스템이 자동으로 저장해야 한다.
- **IMG-004:** 이미지 파일, 이미지 종류, Product ID, Lot ID, Wafer ID와 `nm/pixel` 보정값은 필수값이어야 한다.
- **IMG-005:** 확장자만 보지 않고 실제로 디코딩 가능한 PNG/JPEG인지 확인해야 한다. 파일 형식, 20MB 용량 제한 또는 보정값이 잘못된 경우 저장하지 않고 이해하기 쉬운 오류를 표시해야 한다.
- **IMG-006:** 등록 성공 후 해당 이미지의 측정 화면으로 이동해야 한다.

**의도적인 단순화**:

- Product, Lot, Wafer는 별도 마스터 테이블이 아닌 이미지 레코드의 문자열로 저장해도 된다.
- 중복 이미지 검사, 파일 해시, 메타데이터 자동 추출은 수행하지 않는다.

### 3.2 이미지 목록 및 검색

**목적**: 등록한 이미지를 찾고 측정 화면으로 이동한다.

**기능 요구사항**:

- **CAT-001:** 등록된 이미지를 최신 등록순으로 표시해야 한다.
- **CAT-002:** 각 항목에 썸네일 또는 축소 이미지와 다음 정보를 표시해야 한다.
  - 원본 파일명
  - SEM/TEM 구분
  - Product ID
  - Lot ID
  - Wafer ID
  - 저장된 측정 개수
- **CAT-003:** 하나의 검색어로 파일명, Product ID, Lot ID 또는 Wafer ID를 부분 일치 검색할 수 있어야 한다.
- **CAT-004:** 목록 항목을 선택하면 해당 이미지의 측정 화면으로 이동해야 한다.
- **CAT-005:** 데이터가 없거나 검색 결과가 없을 때 빈 화면 대신 안내 문구를 표시해야 한다.

### 3.3 이미지 표시와 두 점 측정

**목적**: 이미지 위의 측정 위치와 실제 길이를 연결한다.

**기능 요구사항**:

- **MEA-001:** 측정 화면에 이미지가 화면 영역 안에 비율을 유지해 표시되어야 한다.
- **MEA-002:** 사용자는 측정 항목을 `CD`, `Depth`, `Thickness` 중에서 선택해야 한다.
- **MEA-003:** 사용자가 이미지 위에서 시작점과 끝점을 차례로 선택할 수 있어야 한다.
- **MEA-004:** 두 점을 잇는 선과 양 끝점을 이미지 위에 즉시 표시해야 한다.
- **MEA-005:** 실제 길이는 다음 식으로 계산해야 한다.

  `실제 길이(nm) = 원본 이미지 기준 두 점 사이 픽셀 거리 × 보정값(nm/pixel)`

- **MEA-006:** 화면에 이미지가 축소 또는 확대되어도 좌표와 거리는 원본 이미지 크기를 기준으로 계산해야 한다.
- **MEA-007:** 저장 전 현재 측정선의 픽셀 거리와 계산된 nm 값을 표시해야 한다.
- **MEA-008:** 사용자는 저장 전 두 점을 다시 선택해 측정을 초기화할 수 있어야 한다.
- **MEA-009:** 측정 저장 시 다음 정보를 보존해야 한다.
  - 연결된 이미지 ID
  - 측정 항목
  - 시작점과 끝점의 원본 이미지 기준 X/Y 좌표
  - 픽셀 거리
  - 계산된 nm 값
  - 사용한 `nm/pixel` 보정값
  - 선택 입력 메모
  - 생성 시각
- **MEA-010:** 저장 성공 후 측정선과 값이 저장된 측정 목록에 즉시 나타나야 한다.
- **MEA-011:** 이미지 바깥 클릭, 동일 지점 선택, 유효하지 않은 보정값은 저장할 수 없어야 한다.

### 3.4 저장된 측정 결과 조회 및 삭제

**목적**: 측정값의 근거 위치를 다시 확인한다.

**기능 요구사항**:

- **RES-001:** 현재 이미지에 저장된 모든 측정 결과를 최신순으로 표시해야 한다.
- **RES-002:** 각 결과에 측정 항목, nm 값, 픽셀 거리, 생성 시각, 메모를 표시해야 한다.
- **RES-003:** 저장된 결과를 선택하면 대응하는 측정선을 이미지 위에 강조해 표시해야 한다.
- **RES-004:** 페이지를 새로고침하거나 이미지를 다시 열어도 저장된 측정선이 같은 위치에 표시되어야 한다.
- **RES-005:** 사용자는 잘못 저장한 측정 결과를 확인 절차 후 삭제할 수 있어야 한다.
- **RES-006:** 측정값은 소수점 둘째 자리까지 표시하되, 저장 데이터는 계산 정밀도를 유지해야 한다.

### 3.5 요약 정보

**목적**: 등록 데이터가 축적되는 모습을 짧은 데모로 보여준다.

**기능 요구사항**:

- **SUM-001:** 홈 화면에 전체 이미지 수와 전체 측정 수를 표시해야 한다.
- **SUM-002:** 측정값이 있는 경우 측정 항목별 건수와 평균값을 표시해야 한다.
- **SUM-003:** 데이터가 없는 항목은 0 또는 `측정 없음`으로 명확히 표시해야 한다.
- **SUM-004:** 각 집계에는 표본 수 `n`과 집계 기준 시각을 표시해야 한다.
- **SUM-005:** 실제 저장 데이터 KPI와 발표용 예시값 또는 공개 통계를 시각적으로 구분해야 한다.

요약 정보는 별도 분석 대시보드가 아니라 홈 화면의 작은 카드 또는 표로 구현한다. 집계가 없는 항목에 PDF의 예시 숫자를 실제값처럼 표시하지 않는다.

## 4. 데이터 모델 최소안

### 4.1 Image

| 필드 | 설명 | 필수 |
| --- | --- | --- |
| id | 내부 이미지 식별자 | 예 |
| original_filename | 원본 파일명 | 예 |
| stored_filename | 서버 저장 파일명 | 예 |
| image_type | SEM 또는 TEM | 예 |
| product_id | Product 문자열 | 예 |
| lot_id | Lot 문자열 | 예 |
| wafer_id | Wafer 문자열 | 예 |
| calibration_nm_per_pixel | 보정값 | 예 |
| pixel_width / pixel_height | 원본 이미지 크기 | 예 |
| created_at | 등록 시각 | 예 |

### 4.2 Measurement

| 필드 | 설명 | 필수 |
| --- | --- | --- |
| id | 내부 측정 식별자 | 예 |
| image_id | 연결된 이미지 ID | 예 |
| parameter_type | CD, Depth 또는 Thickness | 예 |
| start_x / start_y | 원본 기준 시작점 좌표 | 예 |
| end_x / end_y | 원본 기준 끝점 좌표 | 예 |
| distance_px | 픽셀 거리 | 예 |
| calibration_nm_per_pixel | 측정 당시 보정값 | 예 |
| value_nm | 계산된 실제 길이 | 예 |
| note | 선택 메모 | 아니요 |
| created_at | 생성 시각 | 예 |

### 4.3 무결성 규칙

- 측정은 반드시 존재하는 이미지에 속해야 한다.
- 이미지가 삭제되는 기능은 제공하지 않는다.
- 측정값은 클라이언트가 전달한 값을 그대로 신뢰하지 않고 서버에서도 좌표와 보정값으로 다시 계산한다.
- 측정 생성 후 이미지의 보정값이 바뀌더라도 기존 측정에는 측정 당시 보정값과 결과를 유지한다.

### 4.4 데모 데이터 준비 계약

- **DAT-001:** 데모 시작 전에 브라우저가 직접 등록할 수 있는 PNG 또는 JPEG 이미지가 최소 3개 준비되어야 한다.
- **DAT-002:** 준비 이미지에는 최소 SEM/TEM 구분, Product ID, Lot ID, Wafer ID와 양수인 `nm/pixel` 값이 함께 제공되어야 한다.
- **DAT-003:** 저장소의 TIFF 원천 샘플을 사용할 경우 원본을 수정하지 않고 PNG 파생본을 만든다. 파생본은 원천 `sample_id`, 원천 SHA-256과 변환 시각을 추적할 수 있어야 한다.
- **DAT-004:** TIFF에서 PNG로 변환할 때 픽셀 너비와 높이를 유지하며, `nm/pixel` 값은 리샘플링이 없을 때만 그대로 사용한다.
- **DAT-005:** 데모 데이터는 `PROJECT_AUTHORIZED` 또는 그보다 명확한 사용 승인 상태여야 하며, 출처 상태가 불명확한 이미지는 시연에 사용하지 않는다.
- **DAT-006:** 데모 직전 사전점검은 파일 존재, 이미지 디코딩, 지원 형식, 픽셀 크기, 양수 보정값과 manifest 무결성을 확인해야 한다.
- **DAT-007:** 반복 시연을 위해 SQLite와 런타임 업로드를 알려진 초기 상태로 되돌리는 절차를 README에 기록해야 한다. 초기화는 저장소의 원천 샘플을 삭제하거나 수정하지 않아야 한다.

### 4.5 값과 좌표 규칙

- 모든 저장 좌표는 원본 이미지 픽셀 좌표계에 두고 `0 <= x < pixel_width`, `0 <= y < pixel_height`를 만족해야 한다.
- 픽셀 거리는 유클리드 거리 `sqrt((end_x - start_x)^2 + (end_y - start_y)^2)`로 계산한다.
- 서버 계산값을 기준값으로 저장하고, `distance_px`와 `value_nm`은 유한한 양수여야 한다.
- 화면 표시값은 소수점 둘째 자리에서 반올림하지만 저장값은 반올림 전 정밀도를 유지한다.
- 시각 값은 ISO 8601 형식으로 저장하고 화면에서는 기준 시간대를 명시한다.

## 5. 화면 요구사항

### 5.1 공통

- 데스크톱 브라우저와 최소 1280px 너비의 해커톤 시연 화면을 우선한다.
- 현재 위치와 주요 행동인 `이미지 등록`, `목록으로`, `측정 저장`을 쉽게 찾을 수 있어야 한다.
- 처리 중에는 버튼 중복 클릭을 막고 진행 상태를 표시해야 한다.
- 성공과 실패 결과를 텍스트로 표시해야 하며 색상만으로 구분하지 않는다.

### 5.2 홈 화면

- 첫 진입 경로(`/`)는 홈이어야 한다.
- 상단에는 NANoDB 로고, 브랜드 확장명과 부제, 홈·이미지 목록·이미지 등록으로 이동하는 내비게이션과 실제 데이터 기준의 상태 요약을 표시한다.
- 본문은 대의, 공개 근거, Phase 1 기능 설명, 실제 KPI, 사용 흐름 순서로 배치한다.
- CTA는 구현된 이미지 둘러보기, 이미지 등록, 측정 시작 경로에만 연결한다.
- 자세한 카피, 섹션 구성, 상태와 로드맵 표기 규칙은 `home-tab-requirements.md`를 따른다.

### 5.3 이미지 목록 화면

- 상단: 서비스명, 이미지 등록 버튼
- 요약 영역: 전체 이미지 수, 전체 측정 수, 항목별 평균
- 검색 영역: 단일 검색 입력창
- 본문: 이미지 카드 또는 간단한 표

### 5.4 이미지 등록 화면

- 이미지 미리보기
- 이미지 종류, Product, Lot, Wafer, `nm/pixel` 입력 폼
- 등록 버튼과 오류 메시지 영역

### 5.5 측정 화면

- 왼쪽 또는 중앙: 측정 가능한 이미지 뷰어
- 오른쪽: 이미지 메타데이터, 측정 항목, 계산 중인 값, 메모, 저장/초기화 버튼
- 하단 또는 오른쪽: 저장된 측정 결과 목록
- 선택된 저장 결과와 대응하는 측정선은 같은 강조 상태를 가져야 한다.

## 6. 최소 API 요구사항

구현 방식은 자유지만 프론트엔드와 서버를 분리한다면 다음 기능을 제공한다.

| Method | Path 예시 | 목적 |
| --- | --- | --- |
| `POST` | `/api/images` | 이미지와 메타데이터 등록 |
| `GET` | `/api/images` | 이미지 목록 및 검색 |
| `GET` | `/api/images/{id}` | 이미지 상세와 측정 목록 조회 |
| `GET` | `/api/images/{id}/file` | 이미지 파일 조회 |
| `POST` | `/api/images/{id}/measurements` | 두 점 측정 저장 |
| `DELETE` | `/api/measurements/{id}` | 측정 결과 삭제 |
| `GET` | `/api/summary` | 전체 및 항목별 요약 조회 |

- 성공 응답과 오류 응답은 일관된 JSON 형식을 사용한다.
- 존재하지 않는 이미지 또는 측정 ID는 `404`로 응답한다.
- 입력값 오류는 `400` 또는 `422`로 응답하고 사용자가 수정할 수 있는 메시지를 제공한다.

## 7. 비기능 요구사항

### 7.1 실행 환경

- 로컬 PC에서 명령 1~2개로 실행할 수 있어야 한다.
- 별도 유료 서비스나 외부 API 없이 동작해야 한다.
- 데이터베이스는 SQLite, 이미지 저장소는 로컬 디렉터리를 사용한다.
- 새 환경에서 실행 방법과 데모 순서를 README에 기록한다.

### 7.2 성능과 제한

- 최신 Chrome 또는 Edge를 지원한다.
- 이미지당 최대 용량은 20MB로 제한한다.
- 목록과 상세 조회는 데모 데이터 100건 이하에서 2초 안에 표시되는 것을 목표로 한다.
- 동시 사용자와 대용량 운영 환경은 고려하지 않는다.

### 7.3 안정성

- 업로드 파일명 충돌을 피하도록 내부 저장 파일명을 별도로 생성한다.
- 서버 재시작 후에도 이미지 메타데이터와 측정 결과가 유지되어야 한다.
- 예상하지 못한 서버 오류의 상세 스택을 사용자 화면에 노출하지 않는다.

## 8. MVP 완료 기준

### 8.1 P0 출시 게이트

다음 시나리오가 깨끗한 로컬 환경에서 처음부터 끝까지 끊김 없이 동작하면 핵심 MVP를 완료한 것으로 본다.

- PNG/JPEG 이미지를 필수 메타데이터와 유효한 `nm/pixel` 값으로 등록할 수 있다.
- 등록한 이미지가 최신순 목록에 나타나고 다시 열 수 있다.
- 측정 화면에서 두 점을 선택하면 선, 픽셀 거리, nm 환산값이 표시된다.
- 측정을 저장한 뒤 새로고침해도 같은 좌표의 선과 값이 복원된다.
- 같은 이미지에 CD, Depth, Thickness 측정을 각각 한 건 이상 저장할 수 있다.
- 저장된 측정 한 건을 선택하면 대응하는 측정선이 강조된다.
- 이미지 수와 측정 수가 실제 저장 데이터와 일치한다.
- 잘못된 파일, 누락 입력, 0 이하 보정값에 대해 사용자에게 오류가 표시된다.
- 빈 데이터 상태에서도 화면이 깨지지 않는다.
- 홈의 KPI가 실제 저장 데이터와 일치한다. P1 공개 통계를 표시한다면 출처와 발표 연도를 함께 표시한다.
- 홈의 CTA가 구현된 화면으로 이동하고, 미구현 로드맵 항목은 실행 가능한 것처럼 보이지 않는다.
- README의 실행 절차를 따라 다른 사람이 로컬에서 실행할 수 있다.
- 데모용 PNG/JPEG 이미지 최소 3개와 대응 메타데이터가 준비되어 있고 사전점검을 통과한다.
- 같은 저장 측정을 새로고침 전후로 비교했을 때 각 끝점의 원본 좌표 차이가 1px 이내이고 표시 측정값의 차이가 0.01nm 이내다.
- 서버를 재시작한 뒤에도 등록 이미지와 측정이 조회된다.
- 데모 초기화 절차를 실행한 뒤 알려진 초기 데이터 건수로 돌아간다.

### 8.2 P1 확장 기준

- 단일 검색어로 파일명, Product ID, Lot ID 또는 Wafer ID를 부분 일치 검색한다.
- 저장된 측정 한 건을 확인 절차 후 삭제할 수 있다.
- 항목별 건수와 평균이 실제 저장 데이터와 일치하며 단위와 `n`을 표시한다.

P1 요구사항은 시간이 남을 때 추가하며, P0 출시 게이트를 불안정하게 만들면 제거하거나 비활성화한다.

### 8.3 검증 증거

- 최소 한 번의 P0 전체 흐름 실행 결과를 체크리스트로 남긴다.
- 자동화가 쉬운 거리 계산, 입력 검증, 서버 재계산과 집계는 테스트로 확인한다.
- 좌표 오버레이 복원은 데스크톱 브라우저에서 새로고침 전후를 직접 확인한다.
- 알려진 제한과 미완료 P1 항목은 README에 명시하며 동작하는 기능처럼 노출하지 않는다.

## 9. 8시간 구현 우선순위

| 시간 | 목표 | 완료 결과 |
| --- | --- | --- |
| 0~1시간 | 프로젝트 골격, 데이터 모델, 홈 정적 골격 | 서버 실행, SQLite 테이블 생성, 홈 섹션 노출 |
| 1~2시간 | 이미지 등록 API와 파일 제공 | 이미지 저장 및 재조회 |
| 2~3시간 | 이미지 목록·등록 화면 | 핵심 메타데이터 입력과 목록 표시 |
| 3~5시간 | 이미지 뷰어와 두 점 측정 | 좌표 변환, 선 표시, nm 계산 |
| 5~6시간 | 측정 저장·복원 | 핵심 데모 흐름 완성 |
| 6~7시간 | 검색과 홈 실제 KPI 연결 | 추적성 검색, 건수·평균·기준 시각 표시 |
| 7~8시간 | 오류 처리, 샘플 데이터, README, 시연 점검 | 재현 가능한 최종 데모 |

### 9.1 타임박스 중단 기준

- 각 구간 종료 시점에 해당 결과가 실행되지 않으면 다음 기능을 추가하지 않고 현재 P0 장애를 해결한다.
- 5시간 시점까지 측정 저장·복원이 통합되지 않으면 검색, 삭제, 항목별 평균과 공개 통계 시각화를 즉시 제외한다.
- 6시간 시점부터는 새 기능을 시작하지 않는다. 남은 시간은 P0 오류 수정, 데이터 사전점검, 초기화, README와 리허설에 사용한다.
- 7시간 시점에 깨끗한 환경 실행 또는 P0 전체 흐름이 실패하면 시각적 개선을 모두 중단하고 복구 가능한 마지막 P0 상태를 고정한다.

시간이 부족하면 공개 통계의 그래픽 표현, 디자인 개선, 메모 입력, 측정 삭제, 검색, 항목별 평균 순서로 축소한다. 홈의 대의·핵심 CTA·실제 이미지/측정 수와 이미지 등록부터 측정 저장·복원까지의 흐름은 축소하지 않는다.

## 10. 결정 우선순위와 가정

### 10.1 충돌 해결 순서

문서나 시안이 충돌하면 다음 순서로 판단한다.

1. 이 문서의 P0 출시 게이트와 `constraints.md`의 명시적 제외 범위
2. 이 문서의 기능·데이터·비기능 요구사항
3. `home-tab-requirements.md`의 홈 화면 표현 요구사항
4. PDF 시안과 장기 제품 비전

### 10.2 현재 가정

- 구현과 시연은 한 명이 한 대의 로컬 PC에서 수행한다.
- 인터넷, 외부 계정과 외부 API 없이 전체 데모가 가능해야 한다.
- TIFF는 검증 가능한 원천 데이터이며, 브라우저 데모에는 원본을 보존한 PNG 파생본을 사용한다.
- 보정값은 manifest 또는 사용자가 알고 있는 값으로 입력하며, MVP가 scale bar에서 추론하지 않는다.
- 평균은 저장된 측정의 기술 통계일 뿐 Product, Lot 또는 Wafer 모집단을 대표한다는 의미가 아니다.
- 기술 스택 선택은 위 계약과 8시간 제약을 만족하는 범위에서 Workflow Planning 단계에 확정한다.
